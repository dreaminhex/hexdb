HexDB 2.5.3 shows how to consume streams and queues, right in the admin UI.

## New

- **Streams, live.** Opening a stream on the Streams page subscribes to it, over Server-Sent Events as your own code would, so new messages appear as they're published: by you, by another client, or by the stream's sources. Pause and resume with Watch live.
- **Queues, as a worker.** A queue's card receives up to three messages at a time and shows each one's lease counting down, with Acknowledge (done: deleted) and Release (back for the next worker). Let a lease run out and the message comes back by itself.
- **Code to do it yourself.** "Subscribe from your code" on a stream and "Use it from your code" on a queue give ready-to-run examples, filled in with the hex's address and the stream's or queue's name: Server-Sent Events, WebSocket, reading in order, consumer groups, webhooks and publishing for streams; a worker in curl and Node.js, sending, releasing and extending for queues.

## Changed

- The Queues page shows New queue, Delete, Send and Receive only to users whose roles allow them.
- On a demo hex (`security.demo_mode`), the shared account's Account page no longer shows the password and MFA forms (the server already refused them); API keys still work.

## Upgrading

Restart the hexes one at a time, as usual: replicas first, the Overseer last. Only the admin UI changed.
