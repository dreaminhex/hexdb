HexDB 2.1.2 makes the container image and peer discovery work on platforms such as Fly.io and Kubernetes without changes.

## Changed

- **Container image:** the entrypoint gives the data volume to the `hexdb` user before starting HexDB as that user, so a volume created owned by root (as Fly.io's are) works as it is. HexDB still never runs as root; an image started with `--user` runs as that user, as before. On Fly.io, each hex announces its machine's private address (`<machine>.vm.<app>.internal`) unless `network.advertise_host` is set.
- **Peer discovery:** a peer given by name in `network.peers` is probed at every address the name resolves to, so one name (Fly.io's `<app>.internal`, a Kubernetes headless service, round-robin DNS) finds every hex behind it.
- **Node.js driver:** the package has a default export, so `require("@dreaminhex/hexdb")` works on Node.js 22.12 and later, besides `import`.
