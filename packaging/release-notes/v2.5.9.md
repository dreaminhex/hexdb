HexDB 2.5.9 clears the rest of the open list after the reviews: faster queue stats, sorted pages and SQL; a plugin that falls behind the history waits for a decision instead of skipping changes; API keys show which lattice secret they're on; and releases now publish exactly the image that was tested, plus a slim image.

## Plugins

- **No silent gaps.** A stream plugin whose position the history no longer reaches (a new Overseer that doesn't continue the old history, or a plugin stopped longer than the history kept) used to start at the end of the history, skipping what it missed, with a warning in the log. It now waits, delivering nothing, with `state` `needs_resync` in `GET /plugins`, until an administrator answers `POST /plugins/{id}/resync`: `{"from": "end"}` continues from now; `{"from": "snapshot"}` first sends every current document of its tessellations (`"event": "snapshot"`), then continues.

## Security

- **Lattice-secret rotation status.** API keys listed by an administrator (`GET /auth/keys?all=true`) show `current_secret`: `false` for a key still on a previous secret, which would stop working when that secret is removed. Changes to stored keys (re-hashing, revoking) now run one at a time on the key as it is then, so a key revoked during a rotation can't be written back.

## Performance

- **Queue stats** (`GET /queues/{name}`) come from the Overseer's in-memory index instead of reading every message, and leave out messages past retention that a receive hasn't removed yet.
- **Sorted pages with a range on the sort field** (`rank >= N - 100`, sorted by `rank`) start at the range's bound in the index and stop past the other end, instead of walking the index from one end.
- **SQL** reads only the fields a statement uses (whole documents only for `*`), so narrow queries over wide documents use less memory and fit `limits.sql_max_mb` more easily.
- **Stream offset commits** wait only for commits of the same consumer group, not every group.
- **Stream destinations** keep their connection while the destination's address doesn't change (still checked before every delivery).

## Images

- **What's published is what was tested.** A release builds its image once for both architectures, pushes it by digest, smoke-tests and scans that exact image on amd64 and arm64 (including starting the server and running a script function in each runtime through the API), and only then gives the same digest its version tags and signs it.
- **A slim image**, `ghcr.io/dreaminhex/hexdb:<version>-slim`: the server, the CLI and the admin UI, without Python, Node.js, Tesseract, ffmpeg or curl (script functions are off in it). Less than half the size, with far fewer operating-system packages to patch. Accepted image findings are triaged in `packaging/trivy-triage.md`.
- **ffmpeg's license** (LGPL 2.1) now ships in the image, in `/usr/share/doc/ffmpeg` (it was left out).

## Dependencies

- **wasmtime 48.0.9** (used by the malware scanner's YARA rules): fixes eight advisories published 2026-11-19 (RUSTSEC-2026-0566 to 0573), mostly a Wasm guest aborting the host or growing its memory. HexDB's YARA rules don't run guest code supplied by users, but the update is taken anyway.

## Upgrading

Restart the hexes one at a time, as usual: replicas first, the Overseer last.
