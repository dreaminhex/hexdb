HexDB 2.3.1 makes rolling upgrades lossless. Restarting the Overseer no longer fails a write, a new Overseer carries on the old one's history so replicas stop re-copying everything, and replicas share the data in slices by default. The admin UI also fits a phone screen.

## Changed

- **Slicing is on by default.** With two or more replicas, they share the data in slices instead of each keeping a full copy (the Overseer still keeps everything, and each slice is on at least one replica). The Overseer's setting applies. A lattice upgraded from an earlier release starts slicing when its Overseer runs 2.3.1, and each replica gives up the slices it doesn't keep once another replica holds them. Set `replication.slicing = false` on the Overseer to keep full copies, so every replica serves reads and live feeds from its own data.

## Added

- **Writes are held while the Overseer restarts.** A replica waits up to 30 seconds for an Overseer and passes the write on once one answers, instead of failing it with `502 overseer_unreachable`. A connection the Overseer refused is tried again, since it never reached the Overseer, so no write runs twice.
- **A new Overseer continues the old history.** A replica promoted to Overseer records where it took the old history over and publishes it to the lattice. Replicas at exactly that position continue from there instead of taking a full sync. That's every replica after a handover, and usually all of them after a failover on a quiet lattice. The old Overseer, when it rejoins, continues too.
- **A stopping Overseer hands its role over** (SIGTERM, Ctrl+C, `hexdb stop`, the Windows service, `POST /shutdown`) when the replicas keep full copies. It holds writes, waits until every replica has everything, steps aside, and every hex re-elects at once (`POST /lattice/elect`), in a second or two. In a sliced lattice the Overseer keeps its role across the restart instead, because a new Overseer would first have to collect every slice it doesn't keep. On Fly.io, set `kill_timeout = "60s"`.
- **The admin UI fits a phone.** The Dashboard's cards, the Activity chart, the schema editor and the Tessellations, Users, Audit Trail, Plugins and Configuration tables no longer run off a phone screen.

## Fixed

- HexDB Enterprise rolling updates: the stepping-down Overseer now withdraws as a candidate only once its replicas have everything (a replica could be elected before it caught up), and holds the writes it receives meanwhile for the new Overseer instead of refusing them.
- The runtime file (`hexdb.pid`) is written atomically, so the CLI never reads it half-written.
- The admin UI's dev tools use `minimatch` 11 (GHSA-g3hv-75wg-m249).

## Upgrading

Restart one hex at a time, the replicas first and the Overseer last, each once the one before is back. No write fails. A lattice that upgrades from 2.3.0 starts slicing when its Overseer restarts on 2.3.1.
