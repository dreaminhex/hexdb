HexDB 2.3.2 shows where each hex runs, for lattices spread across regions.

## Added

- **Regions.** Each hex knows its region: `identity.region`, or Fly.io's `FLY_REGION` when it isn't set. It's shared with the lattice, listed for each hex in `/status` (`network.lattice.hexes[].region`, with the lattice's distinct regions in `network.lattice.regions`), and shown next to each hex on the dashboard's lattice card, which also says how many regions the lattice spans.
- The MANUAL has a **Regions** section. A lattice should span three or more regions, so a whole region going down loses no data and the lattice keeps serving. It covers what spreading costs (with `min_acks = 1`, a write waits one round trip to the nearest other region), where to put the Overseer, and how to do it on Fly.io.

## Fixed

- **Fewer full syncs after a handover or failover.** A replica takes over the history only when it applied that history up to exactly the same position as the new Overseer. A replica that was a few changes behind (for example, an internal change the old Overseer made while it stepped down) copied everything again. The new Overseer now also remembers its last 256 positions in the old history, so a replica a little behind resumes from there.
