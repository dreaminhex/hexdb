HexDB 2.1 removes the limits that 2.0 listed: SQL gains joins, subqueries and expressions, there's a JDBC driver, the Entity Framework Core provider supports relationships, owned types, inheritance and explicit transactions, and a lattice can shard its data across replicas. Data directories from 2.0 open unchanged, and nothing changes unless you use the new features.

## New

**SQL**
- **Joins:** inner, left, right, full and cross, with `ON` or `USING`, comma joins with the condition in `WHERE`, and parenthesized joins. Equality conditions make hash joins.
- **Subqueries:** `IN`, `EXISTS`, `ANY` / `ALL`, a subquery as a value, correlated or not, and subqueries in `FROM`. Also `WITH` (CTEs) and `UNION` / `INTERSECT` / `EXCEPT`.
- **Expressions anywhere:** arithmetic, `||`, `CASE`, `CAST`, comparisons between fields, `LIKE` with `_`, `ILIKE`, and string, number, date and NULL functions. Aggregates and `GROUP BY` take expressions.
- **Each table is still read through the query path**, so indexes, permissions, row filters and hidden fields apply as before. Conditions on one table are sent with its read. A read of more than `limits.sql_max_rows` documents (100,000) is refused with a message rather than cut short.
- **Permissions on every table:** a statement needs read permission on every tessellation it reads, including those in joins, subqueries and `WITH`.

**ODBC and JDBC**
- **The ODBC driver reports what the SQL can do:** outer joins, subqueries, unions, and the scalar functions BI tools send in `{fn ...}` escapes, such as `YEAR`, `MONTH`, `LOCATE` and `TRUNCATE`. Tools that read those capabilities can push joins and functions to the server. `{oj ...}` escapes work.
- **A new JDBC driver** (`drivers/java`, `com.dreaminhex:hexdb-jdbc`) for DBeaver, IntelliJ, Spark, reporting tools and plain JDBC code:
  - Java 11 or later, with no dependencies;
  - `jdbc:hexdb://host:7700` with an API key or a login;
  - paged results and full metadata.

  Each release has the jar attached; it's published to Maven Central once the project's Central account is set up.

**Entity Framework Core**
- **Relationships:** navigations, foreign keys, `Include`, `ThenInclude`, string includes and `AutoInclude`, each loaded with one extra query per page of results. Tracked and no-tracking queries are both supported.
- **Owned types:** `OwnsOne` and `OwnsMany` are stored inside the owner's document, and filters can use their properties (`i.Billing.City`).
- **Inheritance:** table-per-hierarchy, one tessellation per hierarchy with a discriminator field. `OfType<T>()` is supported.
- **Explicit transactions:** `BeginTransaction` groups several `SaveChanges` into one atomic HexDB transaction, sent at `Commit`.

**Sharding**
- **Shared shards:** with `replication.sharding = true` and two or more replicas, the replicas share the data's 64 shards instead of each keeping a full copy. The Overseer keeps every shard, and each shard is also kept by `replication.shard_copies` replicas (1 by default), so any one hex can be lost without losing data. A lattice with a single replica keeps full copies.
- **Placement:** rendezvous hashing over the live hexes, the same on every hex, so a hex that joins or leaves moves only its own shards. A replica gives up a shard only once another replica holds it.
- **Failover:** the most up-to-date replica is elected. It collects the shards it lacks from the other replicas and brings them to one consistent point before it serves data.
- **Reads:** sharded replicas pass reads to the Overseer. The dashboard shows how many shards each hex keeps.
- **One limit:** the Overseer still keeps everything, so sharding saves space on the replicas, not on the Overseer.

## Fixes

- The ODBC driver answered three `SQLGetInfo` questions under the wrong IDs and claimed unsupported predicates. Every ID and capability bit was checked against unixODBC's headers.
- The driver test launcher waits for its server to exit before removing the data directory, so CI no longer fails at that step.

## Dependencies

reqwest 0.13, which checks certificates against the operating system's trust store plus `tls.ca_file` (the Debian package now depends on `ca-certificates`); getrandom 0.4, seccompiler 0.5, zstd 0.14, tower-http 0.7 and base64 0.23.
