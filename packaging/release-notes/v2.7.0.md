HexDB 2.7.0 (in progress).

## Point-in-time restore

- **Back to any moment of the last week.** With `backup.continuous.*` set in the lattice configuration, the Overseer ships base backups, file content and every WAL segment to an S3-compatible store (AWS S3, Cloudflare R2, Backblaze B2, Google Cloud Storage, MinIO, RustFS, Tigris), at most `max_lag_seconds` (60) behind the lattice, all of it encrypted with the storage key. `hexdb restore --until <time>` rebuilds a data folder as the lattice was at that moment, documents and file content included, never splitting a transaction. Retention is 7 days by default. `GET /backups/continuous` shows what's shipped and the oldest moment a restore can reach. WAL segments aren't pruned before they're shipped.

## Queues

- **About nine times faster.** A send, receive, acknowledgement, release or extension now stores all its messages in one commit, instead of one commit (and one write to disk) per message. On the benchmark laptop a receive of up to 10 messages took 11 ms instead of 98 ms (median), and consumers took about 1,880 messages a second instead of 204, with or without a dashboard polling the counts (`hexdb_bench -- compare --only queues`). Each call is also all or nothing now: it stores every message it names or none. A dedupe key repeated within one send is skipped like one sent earlier, and a receipt given twice in one call counts once.

## Dependencies

- **jiff 1.0.** HexDB's date and time code (and the patched EXIF reader in `vendor/nom-exif`) moved from jiff 0.2 to its first stable release. Formats on disk, between hexes and in the API are unchanged; the clock's format tests and the SQL, schedule and metadata date tests pass as before.
