HexDB 2.2.0 adds vector search, lets other AI agents ask a lattice questions over A2A, keeps masked fields encrypted even in memory, answers cross-origin browser requests, and makes a lost administrator password recoverable.

## Added

- **Vector search.** A new index kind, `vector`, over a field holding a vector. `POST /{tessellation}/_query` with `near: { field, text | vector, k, min_score }` returns the k nearest documents that match the filter, best first, each with `_score`. Searches respect each user's permissions, row filters and field masks. Exact up to 2,000 vectors, an HNSW graph beyond that, cosine or dot product. With `source` fields, HexDB embeds their text itself through the new `ai.embeddings.*` settings (OpenAI, Voyage AI, Azure OpenAI, GitHub Models, Ollama and other OpenAI-compatible servers), in the background on the Overseer, and re-embeds when the text or the model changes. Text searches count against a per-user daily allowance and the monthly budget. Also in GraphQL (`similar`), the admin UI's index dialog, and the AI tools (`similar`), so the chat, MCP and A2A search by meaning.
- **A2A (Agent2Agent).** With `a2a.enabled`, a lattice publishes an agent card at `/.well-known/agent-card.json` and answers A2A 1.0 JSON-RPC at `/a2a` (`SendMessage`, `GetTask`, `ListTasks`, `CancelTask`; A2A 0.3 clients work too). Answers come from the AI chat as the calling user, under its limits and budget, and are audited as `a2a.message`. Follow-up questions in the same context see the earlier ones.
- **CORS.** `cors.allowed_origins` in the lattice configuration lets the listed web origins (or `*`) call the API from a browser with an API key or bearer token. Credentials are never allowed across origins, so the session cookie and CSRF protection are unchanged.
- **Password recovery.** `hexdb reset-password [--login L] [--mfa-off]`, run on the server's machine, gives a user a new password, unlocks the account, signs out its sessions and can turn off MFA. It works on a running or a stopped server, and as a Windows service, under systemd and in Docker (`docker exec -u hexdb`). It's audited as `user.password_recovered`.

## Security

- **Masked fields are sealed in memory.** Every field any role masks is kept encrypted (AES-256-GCM, bound to its document and field) wherever documents stay in memory: unflushed and cached documents, the change feed's history, idempotency records and WAL records. It's opened only while a request uses it, and indexes hold keyed tokens instead of values. Reads, filters and SQL work as before. `/status` lists the sealed fields under `memory_protection`.
- **No core dumps by default.** The server sets `RLIMIT_CORE` to 0 at startup, so a crash can't write its memory, keys included, to disk. `security.core_dumps = true` allows them for debugging.
- Shards the hex replaces or evicts are overwritten before they're freed.

## Changed

- The chat's question loop is shared by `POST /ai/chat` and A2A.
- `/status` reports `embeddings` (model, documents waiting, last error) and `memory_protection`.
